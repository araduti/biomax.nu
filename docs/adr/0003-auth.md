# ADR 0003 — Authentication

**Date:** 2026-05-10  
**Status:** Accepted

## Context

We need authentication for:
1. Customer accounts (registration, login, password reset, session management)
2. Admin access (internal staff managing products, orders, blog)
3. Future: social login, magic links

Requirements:
- Full ownership of auth data — no third-party SaaS storing user credentials
- Works with our own PostgreSQL (via Prisma)
- Good TypeScript support and Next.js App Router compatibility
- GDPR-friendly (data stays on our infra)
- Not NextAuth v4 (complex, poorly typed) or Clerk (SaaS, data leaves our control)

## Decision

Use **Better Auth** (`better-auth`).

Better Auth is a framework-agnostic TypeScript auth library that:
- Integrates directly with Prisma via its Prisma adapter
- Supports Next.js App Router (server actions, route handlers, middleware)
- Ships email/password, magic link, OAuth (Google, etc.), and 2FA as plugins
- Stores all session and account data in our own PostgreSQL
- Has first-class TypeScript types throughout

## Consequences

- Better Auth generates its own schema additions (sessions, accounts, verifications). These will be managed via Prisma migrations in `prisma/migrations/`.
- We own the full auth stack — password hashing, token rotation, session expiry. We must configure these correctly (see implementation ADR when written).
- Admin role gating is handled via the `User.role` field already in the schema (`"customer"` | `"admin"`). Better Auth's `access` plugin will enforce this.
- No dependency on external identity providers unless we add OAuth plugins later.

## Alternatives considered

| Option | Reason rejected |
|---|---|
| NextAuth v5 | Unstable at decision time; weaker Prisma integration |
| Clerk | SaaS — user data leaves our infrastructure; GDPR complexity |
| Supabase Auth | Couples us to Supabase's DB; we want Postgres freedom |
| Custom JWT | Too much to build and maintain correctly |
