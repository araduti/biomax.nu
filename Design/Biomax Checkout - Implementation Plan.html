1 · Strategy & boundaries

The Kustom iframe handles the entire form: customer details, shipping options, payment selection, totals, and the final Slutför köp CTA. It is mounted inside #kustom-checkout-container and its internal DOM is sandboxed — merchant CSS does not apply.

Inside the iframe, Kustom exposes:

  • 7 themable color tokens + 1 border-radius value (passed via options at order-create time)
  • A ≤70-char shipping_details message on the confirmation
  • A vat_removed boolean to hide VAT

Layout, typography, microcopy, field labels, sequence, and error states inside the iframe are not editable. Therefore every conversion lever lives outside the iframe, in zones we fully control.

3 · Kustom API configuration

Set these options when creating the order via the Kustom Checkout API. Hex values only (no rgba(), no var()).

// POST /checkout/v3/orders — options block
{
  "options": {
    "color_button":            "#1E3A5F",  // deep clinical blue
    "color_button_text":       "#FFFFFF",
    "color_checkbox":          "#1E3A5F",  // radio + checkbox fill
    "color_checkbox_checkmark": "#FFFFFF",
    "color_header":            "#0A0A0A",  // section headers inside iframe
    "color_link":              "#1E3A5F",
    "radius_border":           8,
    "shipping_details":        "Snabb, spårbar leverans · 1–3 vardagar",
    "vat_removed":             false
  }
}

Constraint reminder: do NOT apply any merchant CSS to #kustom-checkout-container or its descendants. Selectors that target inside the iframe will not work and may break the Kustom session.

5 · Points widget integration

The widget sits inside the cart panel, directly above the totals. Default pattern: slider (recommended winner from the exploration — drag-to-redeem with live discount preview removed the friction users had with the 100-point manual input).

Data contract

FieldTypeSource
balanceintegerGET /api/loyalty/balance · cached 60s
stepintegerconst · 100
rateintegerconst · 10 (kr per step)
appliedintegercomponent state, multiple of step, ≤ balance - balance % step

Iframe handoff

When applied changes, suspend the iframe, push a new cart with a discount line, then resume. Kustom recomputes totals and re-renders.

// /src/checkout/points.ts
import { kco } from '@/lib/kustom';

export async function applyPoints(points: number) {
  // 1) freeze the iframe — prevents the user from submitting mid-update
  kco.suspend();

  try {
    // 2) tell our cart service the new redemption
    const cart = await fetch('/api/cart/points', {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ points })
    }).then(r => r.json());

    // 3) push the new cart to Kustom (or rely on session sync if your backend
    //    already updates the Kustom order on cart change). Either path:
    await kco.updateOrder({
      order_lines: cart.orderLines
    });
  } finally {
    // 4) always resume — even on error — so the form is usable
    kco.resume();
  }
}

Optimistic UI

The widget updates its own preview (−X kr) immediately on drag. The iframe stays suspended during the drag and only commits on change (mouse-up). This avoids flooding the API and keeps the iframe legible.

// debounced commit pattern
const [applied, setApplied] = React.useState(0);

const commit = React.useMemo(
  () => debounce(applyPoints, 250),
  []
);

return <PointsSlider
  value={applied}
  onChange={(v) => { setApplied(v); commit(v); }}
/>;

6 · Express-pay strip

Three buttons above the iframe: Apple Pay, Google Pay, Klarna Express. Each completes an order without the user ever filling in the form.

Visibility

  • Apple Pay — show only when window.ApplePaySession?.canMakePayments() === true.
  • Google Pay — show only when google.payments.api.PaymentsClient.isReadyToPay() returns true.
  • Klarna Express — always show. Triggers KlarnaCheckoutExpress.show() from the Kustom SDK.

Layout

  • If 3 buttons available → grid 3 × 1.
  • If 2 → grid 2 × 1.
  • If 1 → full-width single button.
  • If 0 → hide the entire strip including the "eller fyll i nedan" divider.

Success handler

Each express button must dispatch the same order:created event the iframe path dispatches, so analytics, GTM tags, and the loyalty-points-earn job all fire identically regardless of payment route.

7 · Cart panel

Sticky on desktop (position: sticky; top: 16px). Collapsed by default on mobile with a "Visa beställning" chevron.

Sections, top to bottom

  1. Header — "Din beställning · 2 produkter" + "Redigera kundvagn" link back to cart.
  2. Line items — name, sub, qty stepper (− / qty / +), line total. Quantity changes call the same suspend → update → resume sequence as points.
  3. Points widget — slot directly here when applied > 0 OR balance ≥ 100.
  4. Totals — Delsumma · Frakt · (Poängrabatt if applicable, sage) · Totalt (Playfair 24 px). Must mirror what the iframe shows — both totals should come from the same backend source.
  5. Earn-back hint — cream pill: "Du tjänar +N poäng på det här köpet."

Why mirror the totals? The iframe shows its own totals as part of payment. If our cart panel shows a different number, trust collapses. Both must read from the same authoritative endpoint (GET /api/cart/totals).

9 · Mobile specifics

  • Sticky CTA is owned by Kustom inside the iframe — we cannot override its position. Accept this and ensure the iframe has enough breathing room (no fixed footer overlapping its Slutför köp button).
  • Collapsed cart strip at the top — single-line "Visa beställning · 565 kr" with chevron. Tap expands the full cart inline.
  • Member greeting shrinks to a single-line row: badge + "796 poäng" + arrow link "↓ Använd nedan".
  • Express pay stays full-width above the iframe. Buttons stack into a column when viewport ≤ 360px.
  • Trust strip becomes a horizontal scroller (4 cards, snap points, no scrollbar) below the cart so it never pushes the iframe below the fold.

10 · Acceptance & metrics

Acceptance criteria — overall

  • Visual regression vs. the Figma frames at ≤2px diff on key zones (cart panel, express row, points widget).
  • Both keyboard navigation and screen reader can complete an order using express pay AND the standard iframe path.
  • All copy is Swedish. No untranslated strings reach production.
  • Removing the kassan_v2 flag instantly reverts to the old checkout — no DB migrations on either path.
  • Points balance & applied amount survive a page refresh and a browser back-button.

Metrics to watch (week-over-week vs. baseline)

Primary · checkout completion rate
Sessions that hit /kassan ÷ sessions that complete an order. Target +6 pts.
Express-pay attach
Express orders ÷ total orders. Target ≥15% within 2 weeks.
Points redemption rate
Orders with applied > 0 ÷ orders by users with ≥100 balance. Target ≥40%.
AOV

Time-to-pay
Median time from /kassan view to order complete. Target −20% on mobile.
Trust signals

11 · Risks & edge cases

RiskMitigation
Kustom SDK changes the suspend/resume contractPin SDK version. Subscribe to Kustom's changelog. Wrap calls in a thin adapter (/lib/kustom.ts) so a swap is one file.
Merchant cart total drifts from iframe totalBoth must read from the same /api/cart/totals. Add a runtime assertion that compares them on every render in dev mode.
User applies points, then changes shipping in iframeShipping change re-fires updateCart. The points discount is preserved as a line item, not a percentage — it survives shipping changes.
Anonymous / not-logged-in userMember greeting hides. Points widget renders the "Bli medlem" empty state (link to /konto/registrera, prefilled with checkout email). Earn-back hint still shows projected earn.
Express pay returns to checkout (e.g. user cancels Apple Pay sheet)Re-show the iframe with current cart state. No double-render.
Recommendations block adds an item mid-checkoutsuspend → updateOrder → resume same pattern as points. Toast confirms the add. Item is removable from the cart panel inline.
Slow loyalty APIRender the points widget skeleton inline. Don't block the iframe load on balance fetch.
Currency / localeSEK only for now. All toLocaleString('sv-SE'). Hard-coded "kr" suffix is acceptable.
